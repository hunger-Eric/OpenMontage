# 命名角色库与跨项目复用

角色库是本机持久化素材库，独立于 Flow 项目。默认位置为
`$CODEX_HOME/assets/omni-characters`，未设置 CODEX_HOME 时使用
`~/.codex/assets/omni-characters`。角色记录保存名称、稳定 ID、描述、
角色卡的 SHA-256 与库内绝对路径。图片复制到库中，所以原生产目录搬动
不会丢掉角色。远端 Flow 素材绑定仍由原来的项目级缓存负责。

## 创建后命名

展示用户接受的角色卡，然后询问“这个角色叫什么名字？”。用用户给的名字
登记；已经提供名字时直接用，不重复询问，不用未经确认的名字永久登记。
名称尚未回复时可继续独立的场景准备，不把等待命名变成所有工作的暂停门。
不自动把历史人物批量加入库。登记一张合并角色卡；场景不绑定进人物身份。

以下命令中的 Python 为当前环境可用的 Python；脚本入口相对于技能目录。
Windows 中文命令与回读使用 UTF-8（可设 `PYTHONUTF8=1`）。

```text
python scripts/characters.py register --name "小林" --card "<角色卡绝对路径>" --description "低马尾，仓库导购；多视角角色卡"
python scripts/characters.py list
python scripts/characters.py list --query "仓库"
python scripts/characters.py show "小林"
python scripts/characters.py rename "<角色ID或当前名称>" --name "林姐"
```

登记时可用 `--source-project <原Flow项目URL>` 记录来源，不代表建立远端绑定。
同名同图重复登记返回原 ID；同名异图不覆盖旧人物。搜索可按名称或描述查，
返回多个角色时让用户选择；使用时按确切名称或 ID 取角色，不能默默挑一人。
同一角色改名保持原 ID 和角色卡。需要改外貌或服装版本时另行明确版本处理，
不能把查找人物的请求理解为重新生成角色。

## 跨 Flow 项目使用

1. 查询角色，展示名称和角色卡，让用户知道选中的人物。
2. 取得记录中的 `card_path`，沿用这张卡，不重新生成外貌。
3. 在用户指定的目标 Flow 项目中，通过现有 `flow_upload` 关联该文件。
   目标项目已有同 SHA-256 素材时复用；尚无时上传一次。新上传的权限来自
   用户实际的跨项目生产请求，单纯查询不执行上传或生成。
4. 用回执中的目标项目素材身份引用角色。原项目的 mediaId 不能冒充新项目
   的已绑定身份。素材关联成功不等于生成结果的人物一致性已经验证。

这是“跨项目复用同一角色卡”，不是承诺 Flow 支持跨项目直接共享远端素材 ID。
原卡用于人物依据，新场景独立配置。固定的人物外貌和这次可变的衣着、动作
分别写清；角色卡不自动定义声音身份。

角色查询与库操作不提交付费生成，不发送消息。跨设备或账号同步、多人共享
不在当前本机角色库的实现范围内。
