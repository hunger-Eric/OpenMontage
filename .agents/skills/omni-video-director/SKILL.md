# Omni 视频导演

让 Codex 负责叙事与导演决策，让 Omni 根据明确的镜头意图生成或修改画面，再由 Codex 按实际表演完成剪辑。适用于不同题材；人物卡、样片和分镜等按具体任务选用，不要求每次走满全部步骤。

## 入口与使用范围

- 仅查询、登记或改名角色时，直接走角色库说明，不启动视频生产或关联远端素材。用户说“用某角色做视频”时，再把查询结果带入相应生产流程。
- 先辨认本次是方案、样片、完整成片，还是修改已有视频。方案请求只准备方案；已经明确的生产请求持续完成相应交付。
- 用户只说“我有个产品叫 X，帮我写一份视频方案”就使用[人工生成方案工作流](../../../docs/references/manual-video-handoff.md)；在视频技能入口中要求产品视频文案，也按此交付，明确只要文字或先构思时除外。不要求用户罗列参考图和提示词。默认准备必要参考图、分镜和逐镜可复制提示词；只表达构图、表演和镜头意图，不指定视频模型或平台。交付文档后结束本轮；完整视频请求仍走全自动。后续回传素材复用当前项目继续处理。
- 复用已有参考分析、已接受素材、模型选择和创作决定。从用户指定的不满意部分继续，避免每次重新分析或生成整片。
- 本机视频生产沿用 OpenMontage：`E:/project/OpenMontage/docs/CURRENT_PROJECT_STATE.md`、`AGENT_GUIDE.md` 和选定流程的导演技能。Feishu 是输入和交付入口，不建立另一套生产流程。
- 飞书自然语言制作与续改先读[统一创作入口](../../../docs/references/feishu-creative-entry.md)。链接、脚本、场景图和实拍素材可以混用；按目标与材料用途组织制作，同话题补素材延续已知作品，保留用户指定的台词和必用素材。
- 前期脚本、角色、场景和素材工件与视频提供方分离，全自动制作的生成调用沿用 `video_selector` 和[提供方扩展接口](../../../docs/references/video-provider-extension.md)。MCP 与 API 的参数差异由选定适配器处理；本技能的 Omni 表演方法不能被当作其他模型的参数契约。
- 出方案前先读取与当前请求相关的项目约束和流程文件。全自动视频生成再从实际 registry 与已配置 preferences 解析 effective provider；人工生成方案不要求选择或发现视频提供方。agent 传给 selector 的参数只是路由输入，不能冒充用户显式指定；保留用户或项目已锁定的自动生成 provider，能力缺失时报告缺口，不静默切换。
- 新作品合成默认锁定 `render_runtime="remotion"`，不向用户展示 Remotion／Hyperframes 选择菜单。角色、表演和镜头仍按创作目标决定；已有作品继续沿用其明确保存的渲染记录，不能在续改时静默换引擎。
- 在其他环境采用已有项目的权威执行器与工件。工具缺失时说明实际缺口，不自行换模型或创建替代生产系统。
- 创作提示词按需参考 `E:/project/OpenMontage/docs/references/google-omni-video-prompting.md`。它保存官方方法摘要、多场景模板与 Flow 能力区别；仅读取本次相关部分。此参考不可访问时，可查 [官方提示词指南](https://deepmind.google/models/gemini-omni/prompt-guide/)。

## 故事、口播与动作一起设计

明确观众、用途和这段视频要传达的核心信息。把内容写成适合说出口的句子，同时安排人物或物体的行为，让台词与画面有因果关系。口播不是字幕的逐字朗读；必要的产品信息和事实依据来自用户材料或项目研究。

有参考视频时，使用真实画面、声音与既有分析理解其叙事节奏、表演方式和切镜理由。借鉴这些关系，再适配新的内容；不只复制镜头数和时长。没有听到的发音、口音、语气或口型效果保留为未验证。

真人介绍可让人物走向工作对象、拿取物品或演示操作；产品片让使用动作承担说明；科普用可理解的变化表现概念。根据任务确定连续现场说话、画外音或两者结合，不因工具便利擅自改变已接受的声音方案。

连续动作验收必须记录可观察的状态转换，例如“拿杯 → 取下盖 → 嘴部接近/饮用”的起止状态、道具归属和时间区间；中间跳回、瞬移或状态断裂判为不通过。只返修失败镜头并保留已接受镜头。明确要求人物当场说话时，画外旁白不能替代该要求。

## OpenMontage 口播语言分流

Google Omni / Flow 生成人物口播时，以完整视频口播的语言判定：**纯中文必须
换独立中文配音，并按原声的短语、停顿和节奏对齐，保留人物画面**。读取
[中文换声工作流](../../../docs/references/omni-chinese-redub.md) 完成处理与交接。
**纯英文和混合语言直接保留原声**，不做换配音、节奏对齐、嘴型同步或听感专项
检查；混合语言不拆出中文段处理。仅在 OpenMontage 应用此项目默认。

## OpenMontage 背景音乐

按整片内容确定音乐方向，再安排进入、起伏、留白与结束，不按每个生成片段
自带的声音拼出默认配乐。读取[背景音乐工作流](../../../docs/references/music-workflow.md)，
复用已确认来源，在最终口播时间线上安排音乐，交接实际生效的混音方式。
纯英文和混合语言保留整条原声，不因配乐流程增加口播或同步专项检查。

## 建立可复用的视觉依据

涉及角色命名、查询或跨项目复用时，读取
[角色库使用说明](references/character-library.md)，使用
`scripts/characters.py` 操作本机持久化角色库。创建并展示角色卡后让用户命名；
已给名称时直接登记。查库请求只查询，跨项目生产请求再关联目标项目素材。
复用保存的角色卡，不重新生成身份，也不把原项目的远端素材 ID 当成目标项目的绑定。

涉及需要跨镜头保持身份的人物时，优先准备白底多视角角色卡，合并成一张清晰的大图。标明这些视角属于同一人，卡片用于身份、衣着和体态，不要求模型复现拼图。场景另做参考，说明空间布局和人物可活动的位置。产品可用产品图代替人物卡；纯动画无需强行加入真人角色卡。

Codex 组织这些素材与用途，使用当前可用且已选的图像工具制作，保留用户已接受的版本。每次视频请求明确哪份参考提供身份、外形、场景、动作或风格。多视角角色卡与故事板用途不同，避免混用。

在同一 Flow 项目内复用已经绑定的素材身份。通过现有素材复用工具引用，避免重复上传。参考图出现于素材库不等于已经绑定在本次请求中；以实际请求与回执为依据。

## 用表演连续性组织镜头

围绕叙事和动作决定镜头，不固定为“一句口播一段视频”。一个表演可以连续承载多句话；细节镜头可覆盖持续的讲解。

镜头设计保留足够的信息即可：

| 信息 | 导演决策 |
|---|---|
| 本段作用 | 观众此时理解什么、看到什么证据 |
| 主体行为 | 移动、操作、视线与自然手势 |
| 摄影机 | 景别、位置、跟随或固定，是否连续镜头 |
| 声音 | 本段实际说的话、语气、停顿和环境声 |
| 衔接状态 | 入镜与离开时的姿态、道具、方向及对白关系 |

用可观察行为表达“自然”，例如看向操作对象、顺手示意、边走边与同行者交流。避免每个镜头都安排相同的开场站姿、重复手势和收尾微笑。生成时长留有剪辑余地，最终切点依据真实表演决定。

首尾帧可用于需要明确空间或动作过渡的镜头：说明起点、摄影机经过的路径和终点。实际采用入口的首尾帧绑定方式；仅在提示词里写编号不是绑定证明。

## 生成、反馈与对话修改

新方案需要验证时，先选一段能检验人物、场景、动作与声音关系的代表性样片；需要检验衔接时覆盖相邻动作。已有接受结果足够时直接复用，避免额外测试生成。用户只要求样片观感验证时，交付样片后等待其判断；用户要求完整成片时，不自动增加中途确认门。

提示词围绕本次任务组织：参考用途 → 主体行为 → 镜头 → 必要视觉特征 → 对白或声音 → 前后状态。信息够用即可，不叠加固定长度、固定镜头数或冗长质量口号。模型已选定时沿用，技术身份留在参数与回执，不反复写进创作要求或向用户强调。

修改已有素材时，选择原视频或用户认可的版本，在其对话上下文里描述本次变化与保留部分。例如：

```text
把她的黑色上衣改成白色，保留人物、走路动作、背景和原声。
```

```text
让指向箱子的手势更轻一些，像顺手示意，其他部分保持原样。
```

不重写整场戏，不重新上传所有参考。通过现有编辑入口执行；若当前入口只支持准备草稿，报告草稿状态，不能当成已生成的修改结果。保存原素材与修改版本的关系，复用原任务身份查询未知提交，不重复提交副作用不明的请求。

时间范围提示是创作意图，不能直接保证只改某帧或区间。按实际入口区别原生片段选择、提示词时间要求和保存帧图片；精确局部效果需要查看实际输出与区间外变化。官方能力展示、旧预览 API 和当前 Flow/MCP 能力不能互相替代。

## 按实际声音与表演完成剪辑

把生成结果放进项目既有合成工程，复用可用的时间码、素材记录与字幕来源。依据真实动作、对白、呼吸和停顿取舍，而非把供应商片段等长排在一起。

在 OpenMontage 的最终制作／合成提示中，带入[最终制作提示](../../../docs/references/music-workflow.md#最终制作提示)：不要把混音、配音方式、模型、引擎或验收等制作说明显示在画面中。核对实际字幕、角标、片尾卡与其他叠加层，技术信息留在工程记录或随片说明中。

动作或语义承接的细节镜头优先用于过渡；连续环境声可连接空间。避免跨淡化音节来掩盖声音差异。发音、语速或口音出现问题时定位到声音或表演层，只修相应部分，不以反复生成无关画面解决。

用真实成片判断叙事、人物身份、动作、声音和镜头衔接。自动检查只证明其测量对象；听看不到的效果明确未验证。向用户交付所请求的方案、样片或成片和必要证据，不额外生成强制检查、审批步骤或重复工件。发送、发布与部署沿用项目权限和用户实际授权。
