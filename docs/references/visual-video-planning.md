# 通用视觉视频策划流程

## 使用范围

默认先采用用户确定的方向。主题、语言、受众或品牌处理不明确且会实质改变内容时，
先用一个简短问题与用户确定，不自行默认成中文无品牌片。用户已有明确方案时直接沿用，
不重复询问。用户要求多个方案，或所选管线内部需要三套方向时，先用简易文字版列出
各方向的核心想法、表达方式和主要差别，交给用户选择。未经选择，不展开多套完整方案、
脚本、分镜或参考图。选择后只深化选定方向，原有调研照常执行，再交完整看板确认。

普通短片由同一执行器连续完成研究、方案、脚本、分镜和交付，不把每个阶段另行派发并反复轮询。
用户确定方向后，原有调研逻辑、来源数量、事实核实和研究验收完整执行，不作缩减。
阶段和 canonical artifact 仍保留：方案默认一个概念，复用参考分析、
能力快照和已读规范。一个阶段草稿完成后执行一次结构与内容检查；有实际改动或失败才重查，
只修失败字段，不重新生成整套方案。已有参考时不额外做多风格 mood board、三方案或技术路线比选。
这些做法减少重复工作，不降低真实素材、事实依据或完整方案确认的要求。

创意要求和取舍在设计前按用户意见确定，设计阶段把内容、声音、镜头和参考用途写详细。
方案完成后，内容质量、叙事和视觉风格由用户审查；执行器不再做主观评分、优劣比选或润色返修。
内部只做一次技术交付检查：文字无乱码、实际图片可加载且显示比例正常、必要内容齐全、
本项目看板链接与提示词／图片操作可用。沿用已有检查结果，只重查改动或失败项，
不追加审查报告、第二个审查代理或逐字段哈希复审。调研和生成后实际媒体验收保持原流程。

视频方案与自动成片共用这套前期策划逻辑：从用户需求或已有脚本出发，把内容、视觉资产、
生成片段和声音关联起来。执行时沿用现有 pipeline、素材登记和提供方技能；本文不新增入口、
模型路由或状态。文字方向确认复用已有需求沟通，完整看板仍是生成前确认点。
用户仍可只说“我有个产品叫 X，帮我写一份视频方案”。

“视频文案”只交付文字，不启动图片准备；“视频方案”按需要准备实际参考图与可复制提示词，
以[人工方案工作流](manual-video-handoff.md)规定的原生表格或单份文件交付；完整视频请求继续现有自动流程。
方案内容不绑定视频平台。人工方案不发现或选择视频提供方；真正自动生成时才核对实际工具能力。

## 与现有项目阶段衔接

正式视频方案沿用项目已选择的 `pipeline_defs/*.yaml` 和相应 stage director；
本流程与看板是这些阶段成果的视觉组织与交付方式，不另建研究、策划或制作 pipeline。
先核对同一项目的当前 checkpoint、已有工件及已确认版本，复用仍有效的成果；
缺少上游内容时回到所属阶段补齐，不能直接为看板另写一套故事、脚本或分镜。

| 既有阶段／工件 | 看板使用的内容 |
|---|---|
| research／`research_brief`，以及已有参考分析 | 事实与来源、受众、参考作品、视觉／声音依据及待确认事项；研究为方案提供依据，不由看板重做研究 |
| proposal／`proposal_packet`、`decision_log` | 已确定的创意方向、故事主线、受众、时长、画幅及视觉／声音方向，形成方案总览 |
| script／`script` | 对白／口播原文、内容顺序和叙事节拍；看板不得另写或静默替换已确认台词 |
| scene_plan／`scene_plan` | 主体、场景、动作、机位、衔接与镜头编号；按本流程整理成连续生成片段及完整提示词，保留原镜头映射 |
| assets／`asset_manifest` 及项目登记的参考图 | 实际人物／产品／场景图与按需关键画面，使用已有身份、路径和来源；只补缺少的必要参考，不重做已接受素材 |

具体 stage 名称、输入与审批以所选 manifest 为准，不给缺少 research 的既有 pipeline 强加新阶段。
已有脚本、参考分析或锁定方向按既有入口复用；不为了填写看板重跑有效阶段或增加审批。
完整视频项目继续原阶段与审批；只要方案时，交付这些前期成果与必要参考图后结束，
不执行视频、配音、合成等未授权步骤，也不因参考图齐备就把整个 assets 或后期阶段标为完成。
模板/UI 验证可用明确标注的测试方案，但不能冒充正式生产流程通过。

看板入参仅是同一项目成果的交付映射。执行器在该项目保留所用上游工件／版本、片段到原镜头的映射
以及参考图来源，沿用已有工件与交付回执，不把测试 JSON 或线上表格另立为生产状态权威。

## 三类内容各自负责什么

| 内容 | 负责的约束 | 不能据此推定 |
|---|---|---|
| 参考资产 | 产品外观、角色身份与造型、场景空间、整体风格 | 主体已按要求出现在某个位置，或图片已经进入视频模型 |
| 镜头关键画面 | 本段实际构图、主体位置、景别、光线和起始／结束状态；按需要用作首帧或尾帧 | 一张多视角角色卡或氛围图天然就是视频首帧 |
| 视频提示词 | 主体与环境如何运动、镜头如何移动、动作顺序、表演和声音 | 图片编号会被任何平台自动识别，或建议时间会精确执行 |

同一张图可以承担多种用途，前提是对应内容清晰可辨，且本段写明各自用途。
风格参考只约束色彩、材质、画风或光感，不代替人物身份、产品结构或场景布局的依据。

## 共用步骤

### 1. 确定内容依据与叙事

复用已有 brief、参考分析、脚本和已确认决定。有完整脚本时保留用户锁定的文字、顺序与约束；
只有主题或产品名称时先形成创意、内容结构和口播建议，不要求用户填写固定表单。
不虚构真实产品规格或效果；缺少实物图而需要原创外观时，明确标为概念设计。

先写清每段让观众理解什么，再设计主体、动作和空间。口播／对白、屏幕文字、拍摄声音、
音乐方向分别记录，声音继续现有整片规划。没有角色的内容不强造人物。

### 2. 建立最小必要的参考资产

优先复用用户已有、工程已登记或已接受的图。只有缺少本次动作所需的视觉依据时，才沿用
已授权图像路线补图；实际图片、明确设定和图像准备提示／来源一起登记。

| 资产 | 主参考需要明确 | 何时补图 |
|---|---|---|
| 产品 P | 外形、颜色、材质、图案、关键结构；实物或概念身份 | 本段要展示主图看不清的背面、开合状态、内部或局部细节 |
| 角色 R | 同一身份、脸部／头部特征、发型、服装、体型与画风；适用于真人、动漫和拟人角色 | 本段需要全身、背身、转身或新的明确角度；从已接受主图延续，不重新设计身份 |
| 场景 S | 窗户、桌面、背景、关键陈设、光线方向和活动范围 | 新地点或现有空间图无法表达的机位；同地点换机位仍沿用原空间关系 |
| 风格或其他参考 | 明确约束色彩、材质、媒介等哪一方面 | 现有资产不足以表达本次视觉要求时；不为装饰增加无关图 |

角色主图尽量清楚、少遮挡，能辨认必要特征；复杂背景不能淹没主体。多视角卡可用于身份设定，
不必机械准备全套视角。场景空景按组合需要使用，不强制每个场景另做空景。
产品特征不因补角度而改变。参考图之间核对角色造型、产品结构、道具和光线是否一致。

### 动作与空间复杂度决定参考设计深度

人物走动、转身、侧背面出镜、与道具交互或跨场景时，不能只准备一张正面站立图，
再让每个片段自行猜测看不到的身体、服装和空间。设计阶段先从实际分镜列出需要的
角度、全身范围、动作状态和地点，再补齐这些视觉依据；不是统一增加固定数量的图片。

| 分镜需要 | 角色参考设计 | 场景参考设计 |
|---|---|---|
| 固定站位、正面口播 | 清楚的身份、服装和本镜头所需景别；现有主图够用就复用 | 明确站位、背景与光线；不机械补全套视角 |
| 走动、转身或镜头绕拍 | 必要的全身正面、侧面／三分之四面、背面；能看到实际会出镜的鞋、下装和服装背部；从同一主设定延续 | 地面与可走路径、出入位置、陈设间距和遮挡关系；补实际机位会看到的空间部分 |
| 坐下、弯腰、拿取或递交道具 | 按动作补起始／关键状态，明确手、道具、身体姿态及衣着关系；不把每个动作另设成新角色 | 道具位置、可触达范围、桌面／货架高度和角色相对位置；必要时设计组合关键画面 |
| 同一角色跨地点或连续换机位 | 跨场景共用身份和服装设定，注明有意的造型变化；补新镜头需要而已有图看不清的视角 | 每个实际主场景明确空间、光线和活动区；同一地点换视角保持陈设、方位和进出方向一致 |

在已有角色／场景资产记录中写明每张图约束什么，以及哪些片段、视角和动作使用它。
连续镜头在分镜和提示词中写清进入／离开方向、起止位置、姿态和道具状态，不能只写
“同一个人物、同一个场景”。多视角设定卡仍是身份参考，实际镜头首尾帧按构图需要另行
使用组合画面，不把整张视图拼图当作视频场景。参考越复杂越应共用稳定设定，而不是
每段重新设计一套人物与环境。这些工作在设计时完成，不新增人工确认点、主观评分
或重复审查；原有技术交付检查和用户完整方案审查保持。

沿用现有素材登记，以稳定编号记录主体、角度／状态、来源、用途和关联片段。继续使用
`P`／`R`／`S`，组合画面用 `C`；其他前缀按项目需要扩展。编号只是方案内部标识。
必要参考没有实际文件或可辨内容时保留缺口，不以文字、路径或占位图声称已经备齐。

### 3. 按连续内容组织生成片段

叙事节拍、创作分镜与一次生成片段分别记录。一个片段可以包含“拿取 → 展示 → 使用”等
连续动作；段内节奏写入同一完整提示词，不把每几秒的小分镜自动变成独立生成任务。
按动作复杂度、明显的空间／主体切换、关键细节控制和用户要求决定是否分段，不固定时长或数量。

每段记录目的、原分镜映射、建议规格、主体动作、起止状态、所用图片及用途、台词原文、
后期屏幕文字和前后衔接。只选择本段需要的参考，不把整份资产库塞进每段。

### 4. 决定是否需要镜头关键画面

两种方式都可用，策划按构图与动作需要选择，用户无需选择技术模式：

- 必要参考图组直接配完整视频提示词：人物、产品、场景的角色清楚，构图可用文字表达时，
  不强行增加中间图片。自动执行须确认当前工具实际支持所需参考用途。
- 先用已接受的参考组成镜头关键画面，再配视频提示词：需要明确手与产品的接触、多个主体
  的位置、视线、产品朝向或特定景别时，按需准备本段起始画面。结束姿态确有控制需要时才补尾帧。

选择关键画面时，写明来源关系，例如 `P01 + R01 + S01 → C01 → G02 首帧`，并准备实际图片。
构图描述包含主体位置、手与道具关系、机位、光线和动作开始前的状态；沿用来源主体与空间，
不把新的组合图变成另一款产品、另一个角色或另一个地点。角色多视角拼图不可直接冒充场景首帧。

“只交付方案”时不探测员工将使用的平台；文档写明图的预期用途与可复制的创作提示即可。
不假定所有工具都支持多图、尾帧或相同的时长；员工按自选工具实际支持的入口使用图片。
后续若发现必要用途无法承载，补齐适合该入口的组合画面或报告缺口，不默默丢弃必要参考。

### 5. 分别写图片准备提示与完整视频提示

图片准备提示负责静态内容：主体与来源约束、角度／状态、构图、空间、光线与风格。
复用图时记录实际来源，无需为已经接受的图重复编写新生成任务。关键画面的图片提示按需提供，
与本段动态视频提示分开，避免复制时混淆。

每个生成片段始终有一条自洽、可独立复制的视频提示词，包含：

1. 本段所用图片及明确用途、必须延续的身份／产品／空间特征。
2. 起始构图与状态、连续动作与表演、主体及环境运动、景别与运镜。
3. 动作顺序或必要的相对节奏、结束状态及前后连续性。
4. 需要生成的现场对白／声音；只有后期添加的口播、字幕或屏幕文字另列，避免要求模型写入画面。

已有首帧时，简要说明沿用画面并把文字重点放在运动、表演与时间推进；不要再描述互相矛盾的
外观或起始位置。没有首帧时，补足构图与位置描述。完整 prompt 与台词栏共享同一原文，
不使用某个平台专属参数、引用语法或按钮说明。时长与画幅规格另列，建议时间不作精确承诺。

### 6. 交付或继续生成

人工方案把实际图片、来源／用途、片段、口播和提示词放入同一份原生表格或固定模板文件，批量写入，
保留可编辑文字。飞书入口默认使用[原生多维表格](feishu-video-plan-base.md)，不先制作 Office 文件。
原图继续留在工程，方便员工取用或以后自动续作；表格或文档显示图片不代表已传入模型。
交付后本轮结束，不后台等待或自动提交视频。

自动生成沿用现有提供方技能，把图片真正传入对应的主体参考、首帧或尾帧入口，核对上传与关联
证据；不能只写“参考图片”或只用编号代替图片。所需用途无法关联时报告具体缺口，
不降为无图生成。生成后检查实际身份、产品、空间、动作与连续性，回执不替代画面验收。
自动与人工执行统一在既有 `scene_plan` 节点展示完整方案和必要实际参考图，写入 `awaiting_human`，
用户确认这一版本后再继续。不再默认制作十秒样片或在素材生成后第二次等待人工确认；
自动方式执行整片并保留内部验收，人工方式等待同项目视频回传。平台发布仍单独授权。

## 一段人物与产品互动的关联示例

以下仅示意结构，制作真实方案时以实际内嵌图和一条完整 prompt 替换：

| 项目 | 示例 |
|---|---|
| 已接受资产 | P01 概念咖啡杯外观；R01 同一角色的主参考；S01 窗边桌面空间 |
| 片段 G02 | 同一窗边环境，人物拿杯、短暂展示并饮用；关联原分镜与相邻片段 |
| 参考直接使用 | 图 1 P01 约束杯型与图案；图 2 R01 约束身份与服装；图 3 S01 约束空间与光线 |
| 按需起始画面 | 互动位置需明确时，P01 + R01 + S01 组成 C01：人物坐在桌边，杯子在右手可触及处，尚未拿起 |
| 关键画面用途 | C01 用于 G02 首帧；P01／R01／S01 是其来源，不自动变成额外必须上传的首帧 |
| 动态提示重点 | 从对应起始状态伸手拿杯，展示后饮用；写清手与杯的关系、运镜和结束姿态，保持杯型、人物和空间连续 |

## 验收与效率边界

验收以实际产物为准：必要图确实存在且内容一致，图片用途和片段关联明确，图像准备提示与动态
提示分开，台词原文一致，交付中的图可见且长 prompt 完整可复制。选择首帧／尾帧时检查真实画面与状态，
未选择时不机械增加图片。真正生成后另验上传绑定与视频效果，方案通过不等于视频通过。

复用接受的资产、按需补角度／关键画面、集中批量写入可以减少重复工作；不在交付制作时反复重写
策划，不默认输出多格式。实际耗时与画面改善仍需真实任务验证，不承诺未经测量的提速比例。
