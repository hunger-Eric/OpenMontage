## 官方方法摘要

依据 [S1](https://deepmind.google/models/gemini-omni/prompt-guide/)：

| 方法 | 提示重点 |
|---|---|
| 新视频 | 景别、运镜、风格、光线、地点、动作 |
| 自然表达 | 说明创作意图，复杂动作不必逐帧规定 |
| 迭代编辑 | 只描述本次修改，无需重写整场戏 |
| 镜头指挥 | 连续镜头、固定机位、推进等明确意图 |
| 多模态参考 | 组合图像、视频、文字、音频并说明关系 |
| 一致性 | 用参考素材约束人物、物体和环境 |
| 风格转换 | 描述目标风格及需要保留的运动细节 |
| 故事板 | 用视觉分镜表达事件顺序 |
| 首尾帧 | 说明起点、过渡路径、终点画面 |
| 屏幕文字 | 说明字体、位置、出现方式和节奏 |
| 声画关系 | 说明画面动作怎样配合声音 |

## 应用方式：先决定素材承担什么作用

同一份素材可服务不同目的，提示词应说清这次的用途。以下分类是项目的创作组织方式。

| 目标 | 输入组织 | 提示词着重说明 |
|---|---|---|
| 从零创作 | 文本；按需要补参考 | 主体在做什么、空间关系、镜头怎样观看 |
| 保持人物一致 | 人物参考，独立场景参考 | 人物身份与场景分别来自哪份素材 |
| 产品演示 | 产品图、可选场景图 | 产品外形、使用动作、镜头关注的功能 |
| 动作迁移 | 动作视频、目标人物或物体参考 | 哪份素材提供动作，哪份提供外观 |
| 改已有视频 | 指定原视频，必要时补局部参考 | 改什么，以及需要保留什么 |
| 风格转换 | 原视频、可选风格图 | 改变材质或视觉语言，保留动作与事件 |
| 故事板创作 | 有顺序的分镜图 | 阅读顺序、关键事件、镜头之间的关系 |
| 声画配合 | 可用的音频参考或声音描述 | 动作与声音如何对应，而不只写“有音乐” |
| 镜头衔接 | 前镜头收尾、下一镜头目标画面 | 姿态、运动方向、道具状态与运镜路径 |

参考名称是说明角色的占位符，不代表 Flow 已经绑定了素材。实际使用时替换为界面中已选的素材名称或编号。角色卡用于身份，故事板用于事件顺序；多人或多视角拼图应说明各格含义，以免把参考图布局当成最终画面。

## 新视频提示词：信息够用即可

可以按下面顺序组织，但无需每次填满全部项目，也不设提示词长度门槛：

```text
任务：这段视频要让观众看见或理解什么。
参考用途：人物 / 产品 / 场景 / 动作分别来自哪份素材。
动作：主体怎样移动、操作或与其他对象互动。
镜头：景别、机位、运动方式，是否连续镜头。
视觉：只补与表达目标有关的风格、光线和环境。
声音：需要的对白、语气、环境声或音乐关系。
衔接：如有前后镜头，说明进入与离开时的状态。
```

优先写可看见、可听见的行为。例如用“边走边与同行者交谈，转头看一眼箱子”替代只有“自然、生动”的形容词。细节服务于目标；相互矛盾的机位、动作与时长要求应在创作时简化。模型、画幅和时长已有界面参数时，不必在每次提示词中重复模型名称。

## 原创示例：多种场景

以下是起点模板，不是逐字照抄的固定配方，也没有经过本轮媒体生成验证。

### 真人介绍 / 仓库、门店、展厅

```text
人物参考提供同一位女性的外貌，场景参考提供仓库布局。
她沿通道边走边向同行者介绍发货流程，看到左侧箱子时轻轻示意。
镜头平稳后退，与她保持相近距离，连续拍摄，能看到脚步和货架的视差。
她用日常普通话说：“发货前，我们先核对数量，再检查每一箱的包装。”
语气像与同事交谈，保留轻微脚步和仓库环境声。
结尾她仍面向箱子，方便接下一个包装检查镜头。
```

中文发音、口音、语速和口型需要听看实际结果；这段写法不是普通话质量保证。需要一致声音时，可研究当前产品可用的声音参考或声音配置，沿用既定生产方案，不能仅凭文字假定声音身份已绑定。

### 产品演示

```text
产品参考是这只保温杯的外形依据。杯子放在早餐桌上，一只手打开杯盖，
倒出热水，再把杯盖轻轻放回。镜头从中景缓慢靠近杯口，晨光从侧面进入。
保持杯子的轮廓和标志位置，重点表现开合方式与热气，配真实桌面声音。
```

### 动作与外观来自不同参考

```text
动作参考提供滑板转弯的运动节奏，人物参考提供滑手的外貌与服装。
让这位滑手在新的海边步道完成相同类型的转弯，摄影机从侧后方跟随。
环境采用傍晚自然光，强调轮子与地面接触的运动感。
```

这表达的是动作迁移意图，不承诺复制每一帧轨迹；实际输入类型与长度仍取决于使用入口。

### 科普 / 动画

```text
用黏土动画展示雨水怎样从地面汇入小溪，再流入河流。
镜头沿水流方向缓慢移动，以地形变化解释过程。
保持地理关系易于理解，让水流运动承担说明，不堆叠文字标签。
```

视觉可信不等于事实正确。科普所需事实依据继续来自项目研究材料，不能把模型的世界知识当作资料核验。

### 故事板 / 多个事件

```text
按故事板从左到右阅读：快递员到门口，住户开门，双方交接包裹。
保留同一人物和包裹，事件顺序清楚；把镜头时间主要留给交接动作。
```

事件太多时，可按叙事需要分段制作；若某段表演本来连续，也可保留连续镜头。这里不预设“一句文案生成一个镜头”。

### 首尾帧 / 空间转场

```text
起始画面是杯子的近景，结束画面是整张早餐桌。
镜头平稳拉远并稍向右移动，逐步露出餐盘和坐在桌边的人。
保持桌面空间关系，整个过渡是一个连续镜头。
```

首尾图需要通过入口支持的首帧 / 尾帧方式绑定，仅在文字里写“第一张是首帧”不证明绑定成功。

## 已有视频：用修改意图继续对话

优先以已选视频或已接受的版本为基础，传递本次变化。项目示例：

```text
把她的黑色上衣改成白色，保留人物、走路动作、背景和原声。
```

```text
让她指向箱子的动作更轻一些，像顺手示意；其他部分保持原样。
```

```text
把这段改成水彩动画风格，保留人物的移动方向、事件顺序和对白。
```

一次迭代围绕一个明确修改目标，便于判断结果。修改衣服时不必再次复述整个人物传记、场景建筑和原始生成过程。保留要求是模型指令，并不证明未提及区域逐像素不变。

## 平台能力与提示方法分开看

截至核对日，[S3](https://support.google.com/flow/answer/16352836?hl=en) 列出了 Flow 的首尾帧、参考素材生成及最长 10 秒视频编辑，并将 Omni 延长视频列为尚待提供的功能。[S1](https://deepmind.google/models/gemini-omni/prompt-guide/) 则展示了延长镜头的用法。两者覆盖的产品入口或发布状态可能不同：在 Flow 中采用实际可用功能，不把模型展示当成当前 MCP 已实现能力。

依据 [S4](https://support.google.com/flow/answer/16935718?hl=en)，Flow 可在裁剪窗口选择最多 10 秒片段，再写编辑要求；编辑历史保留原版本，连续细化上下文有最多三轮的说明。暂停保存某帧是提取图片，不能据此推断“仅编辑这一帧”。

当前 MCP 的 `flow_video_edit.scope` 只把时间范围写入提示词，不能当作原生裁剪或精确编辑遮罩。时间码表示意图；声称精确局部修改，仍需真实范围绑定和区间外结果证据。本轮只沉淀指南，不新增这类实现或生成验证。

项目已有 `gemini-omni` 技能正文主要描述旧预览 API 入口。其参数、语言支持、价格与功能限制不能直接套在 Flow 上；采用 API 时另查对应接口最新官方文档与本地工具契约。
