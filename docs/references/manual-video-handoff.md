# 人工生成方案工作流

## 适用范围

这是 OpenMontage 原有流水线的前期方案交付模式，不是独立策划流水线。用户只说“我有个产品叫 X，
帮我写一份视频方案”时，即可作为常规入口，不要求用户先提出人工生成术语、枚举交付物或选择模型。
方案默认包含创作分镜、必要的真实参考图，以及各生成片段的完整可复制提示词，交付方案即完成；完整视频请求
仍走自动成片流程。用户明确要求“交给员工在网页生成”“只给我图片和逐片段提示词”时，也在参考图
与各片段提示词准备完成后交付方案，本轮任务即完成。只要求文字或先构思时尊重文字范围，不生成图。
也可在既有制作中按用户要求停在同一交接点，不增加新的生产状态或审批步骤。

示例请求：

> 我有个产品叫 X，帮我写一份视频方案。

也可点名现有入口技能，后面仍只写一句产品需求：

> 使用 ai-video-gen 技能。我有个产品叫 X，帮我写一份视频方案。

“视频方案”包含参考图、分镜和各生成片段的完整提示词；“视频文案”是纯文字交付，不生成图片或视频。
即使点名这个技能，也不把文案请求升级为带图方案；明确“只要文字”时同样只输出文字。

## 交接前

### 必须先执行原有前期阶段

1. 按需求选择已有 pipeline manifest，初始化或续用同一项目，读取当前 checkpoint 与有效工件。
2. 执行所选 manifest 的研究 director，保存并校验 `research_brief`；复用已有有效研究时保留其来源，
   不凭测试方案或看板文字声称完成研究。研究量、资料要求及适用例外沿用该 director。
3. 依次执行 proposal、script 与 scene_plan director，保存 `proposal_packet`／决定、`script`、
   `scene_plan`，完成所属阶段的 review 和既有审批。不得先写看板再倒填这些工件。
4. 进入原 asset director 的参考素材准备部分，按已确定分镜复用或补齐必要人物、产品、场景和关键画面，
   保留实际图片与素材登记。只做方案时不调用视频、配音、音乐或合成步骤；素材记录如实反映部分范围，
   不伪造整个 assets 阶段通过。
5. 将以上既有成果映射到固定看板，经图片、正文、关联和复制读回验收后，仅交付独立看板网页。

这些是原流水线的阶段执行要求，不另设状态机、提供方路由、研究器或额外审批。
实际阶段名称及顺序以匹配的 manifest 为准；输入为已有脚本／参考分析时沿用项目现有复用规则。
过程工件、来源和检查记录留在本地项目；飞书不需要增加研究、脚本等过程页面，最终只返回看板结果。
未达到所选流程的既有审批时按原规则停在对应节点，不能以“过程不展示”为由跳过。

前期沿用[通用视觉视频策划流程](visual-video-planning.md)：参考资产约束主体与空间，镜头关键画面
按需要明确构图和起止状态，视频提示词描述后续运动。必要多参考直接使用与按需先组成首帧都保留；
不强制每段生成关键画面，也不因编写人工方案探测或选择视频平台。
正式方案先按该流程的“与现有项目阶段衔接”核对所选 pipeline 的 research、proposal、script、
scene_plan 与已登记参考资产；看板／文件交付只映射同一项目的阶段成果，不另建策划链或生产状态。

1. 信息不全时先合理设计并标明方案建议；只对实质影响内容的缺口问一个简短问题，不要求固定表单。
   不虚构真实产品规格或品牌外观；只有名称且暂无产品图时，产品视觉示意标明为概念，不当作真实商品。
2. 新需求沿用现有前期流程完成方案与分镜；已有作品则复用同一 brief、scene plan、参考分析和创作决定。
3. 按当前项目授权优先复用用户已有可用图；有持续、具名、真人、动漫或拟人角色时，设计或复用能锁定
   身份、外貌、服装与气质的角色参考图。每个不同主场景设计或复用能表达空间布局、光线、关键陈设
   与构图的场景参考图；必要的产品、角色和场景图缺少实际文件或可辨内容时，不能声称视觉方案完整，保留缺口。
   缺少必要图时才按已授权图像路线补齐；纯产品且无人时不强造角色，文字文案仍不生成图片。
   产品存在交互或外观依赖时准备产品参考图；角色、场景、产品一起使用时保持视觉一致，不把明显不匹配
   的合图当作连续首帧。合图若角色／场景确实清晰可辨可承担多用途，必须标明各用途；含糊氛围图、文字
   或占位图不能冒充独立明确设定。同角色同场景跨片段复用，不重复生成。沿用现有素材登记，保留实际
   原图与片段的对应关系；文档中的图序和用途应能追溯到工程素材。
   参考资产按稳定编号登记：产品用 `P`、角色用 `R`、场景用 `S`、合图或其他组合用 `C`，可按项目
   扩展前缀。每张或每组图都写主体名称、角度／状态、用途和关联片段。产品记录外形、标志、材质及
   所需视角或细节；角色记录身份、服装、体态和必要视角；场景记录布局、光线、陈设和活动范围。
   按需要补齐，不固定图数，也不为每个动作单独生成图。
   一起使用前核对产品结构与图案、角色造型、环境光线和道具是否一致；真实产品图和用户已锁定的
   设定作为对应内容依据，概念图不能悄悄替换。新增视角应延续同一主体，不重新设计身份或产品外形。
4. 按一次人工生成的视频片段组织交接：每段准备一组必要参考图和一条自洽完整提示词，
   并给出该生成片段与已有 `scene_plan` 镜头编号的映射。段内几秒的分镜、动作和相对时间建议
   写在同一提示词中，不自动拆成独立生成任务。
   本段需要明确人物与产品接触、多个主体位置或特定景别时，按需从已接受参考组成实际关键画面，
   记录来源编号、构图、起止状态及首帧／尾帧用途；不把多视角角色卡当作镜头首帧。
5. 沿用已确认的台词、人物／产品身份、动作连续性和前后状态；只询问会实质影响交付的缺口，
   不重新询问已经确定的制作偏好。

## 交付工件

飞书入口默认使用[原生多维表格交付](feishu-video-plan-base.md)，以实际图片附件和真实关联记录
组织总览、资产与片段，返回独立看板网页链接；后台 Base 链接不作为交付入口。
不先创建 Word／Excel，也不走 Office 排版和渲染检查。
图片与动态提示词的内容要求仍相同；原生 API 不可用时保留方案与具体缺口，不静默退回文件路线。

本地文件交付或用户明确要求 Word 时，提供一份固定版式、纵向图文、自包含且平台中立的方案，保存为
`artifacts/manual-video-handoff.docx`。Markdown 可保留为项目内部草稿，但不作为外部附图交付。
文件路线的 Worker 输出附件只包含这份最终方案文档，不另列图片附件；每个生成片段使用一个纵向版块，
版块内直接嵌入一组必要参考图，并放置对应的完整提示词。原图仍在工程内登记并供后续复用。
用户明确要求 Excel／XLSX 时才沿用[Excel 模板](../templates/manual-video-handoff.xlsx)，保存为
`artifacts/manual-video-handoff.xlsx`；本轮只交付用户要求的格式，不默认同时制作多种版本。

以下字段同时适用于原生表格和文件方案；Word 使用开头总览、参考资产图文区和片段纵向版块：

| 字段 | 内容 |
|---|---|
| 片段 ID／原分镜 | 与后续回传一致的片段编号，以及关联的原分镜编号 |
| 整片位置／片段规格 | 整片中的位置、建议片段时长与画幅；段内相对节奏单独记录 |
| 场景与画面动作 | 场景、主体位置、交互关系、动作、起止状态和镜头意图 |
| 内嵌参考图组 | 实际嵌入的图像，标明稳定编号、图序及身份／外观／空间／风格／首帧／尾帧用途；合图多用途时分别说明 |
| 按需关键画面 | 来源资产编号、构图与起止状态、图片准备提示／来源及实际图；无需时删去该项，不增加图片任务 |
| 口播／对白原文 | 本片段完整台词，用户已锁定时逐字保留；无需口播则写“无”，区分画外音与现场口播 |
| 屏幕文字 | 无则写“无”；字幕／标题与口播内容分开记录 |
| 完整生成 prompt | 一条可独立复制的主体、动作、镜头、视觉、声音和前后状态提示词 |
| 前后衔接 | 与前后生成片段或原分镜的姿态、道具、方向和声音衔接 |

下列内嵌、版式和导出要求适用于文件路线；原生表格使用对应的附件、关联记录与 API 读回验收，
不执行文档制作步骤。

参考资产图文区集中展示实际内嵌图、稳定编号、明确设定、图像准备提示／来源和关联片段；每个生成片段版块
直接嵌入本段参考图组，并列出图序和各自约束，再放置一条可复制的完整 prompt。图片必须真实写入
文档内容，不能用本机路径或外部图片链接冒充内嵌图片；文字保持可编辑，不能做成文本截图。
沿用固定模板样式批量填充内容，导出后全页预览，确认图片显示完整、片段顺序正确且 prompt 可复制，再登记最终交付。
每条提示词必须自洽，并用相同的稳定编号或明确主体语义引用所用参考图，写清景别、构图、主体位置、光线／环境、人物与产品动作、运镜、
真实对白（如有）、段内相对节奏及与相邻片段的前后状态。以创作意图表达要求，不绑定某个平台的提示词语法。
图片编号是方案内部标识，图序是该片段实际使用的顺序；两者都应与本段内嵌图一致，不假定编号文字
会被某个平台自动解析。参考组只选择该段需要的图，不能把整份资产库无差别塞入每段提示词。
图片准备提示与动态视频提示分开；使用关键画面时说明来源，如 `P01 + R01 + S01 → C01 → G02 首帧`。
本段把 C01 用作首帧，不意味着其来源资产还必须全部作为额外视频输入。已有首帧时动态提示重点
写动作、表演、环境运动与运镜；没有首帧时补足本段构图与主体位置，保留一条完整可复制 prompt。
口播／对白列与 prompt 中的对白必须来自同一内容依据并保持原文；仅后期添加的屏幕文字不得写成模型需要生成的画面文字。
必要拍摄声音可以归入同一生成片段；音乐沿用现有整片规划，不要求每行生成新的音乐。
不要写内部 asset 路径、MCP 参数、selector 调用、私有 receipt 或实现细节。合图或首帧按需要使用，
不能把角色多视角拼图当作要求模型复现的场景或首帧。视频提示词
与时长／画幅规格分开写；不指定视频模型、平台、账号、页面按钮或 API 参数，
不强制每段 10 秒，也不强制每段参考图数量或重新生成；可复用人物、产品和场景图。按动作复杂度、
人物／场景切换、关键细节控制或用户明确要求决定是否分段。整片范围规划与片段内相对节奏分开记录，
建议时间不是模型精确执行承诺。人工方案无需发现或选择视频提供方；图像准备仍沿用现有图像工具。
若当前执行环境没有实际导出自包含 DOCX 的能力，报告该交付缺口，不默认退回逐张图片发送。

### 模板与排版

本节与下一节只适用于明确选择的 Office 文件交付；飞书原生表格不执行这些步骤。

沿用[视频方案 DOCX 模板](../templates/manual-video-handoff.docx)，复制到项目后填写；文档包含开头总览、
参考资产图文区和生成片段纵向版块。用户只收到这一份文件，不另发图片附件；不输出默认多格式版本。
作品名称、产品、受众、总时长、画幅和声音方向放在开头总览，其后依次是参考资产图文区和片段版块。

- 使用清晰的中文字体、温暖浅色底和深色标题，以少量强调色区分层级；用留白和浅色段落底纹
  组织内容，不用密集粗边框、装饰徽章或制作说明占据画面区。
- 图片随正文内嵌排布，避免浮动定位；片段编号和规格简洁，正文自然分页，不强制每个片段占一页，
  也不通过缩小字体塞进一屏。
- 每个片段版块的图片保持比例，场景、口播和完整提示词按内容纵向排布，保证长文本完整可读。
- 模板示意内容和图片占位只用于说明版式，交付实际方案时替换为本项目内容及真实内嵌参考图，
  不把占位格或模板示例当作已经生成的素材。输出前按片段核对内容对应关系并全页预览。
- 参考资产图文区的图像准备提示只说明如何准备或复用图，不替代实际内嵌图；缺图时保留缺口。

### 集中填充与验收

1. 复制固定模板到本项目的新输出，复用模板样式和已经接受的参考图；先确定一次方案正文、
   片段与图片映射、图序和所需嵌图位置，不在排版期间反复重新设计内容。
2. 在飞书 Worker 中沿用其 OfficeCLI 文档技能，以一份批量写计划集中替换文字、扩展片段版块并插入图片。
   优先使用实际支持的 atomic batch；不逐单元格往返，也不每段重新探索同一套命令或设计样式。
   填充前一次读回模板段落，优先按稳定段落标识定位；多行文字可能形成多个段落，不能靠预估段落序号写入。
   图像准备和内容策划仍由既有流程负责；批量操作只负责按已确定的内容制作文档。
   必须的 Office 内容操作不受支持时报告具体缺口，不静默换 Office 引擎。
3. 保存或关闭文档后，读回相关内容并分别执行 `validate`、`view issues`，对版式敏感的 DOCX 渲染并检查全部页面。
   核对图片可见、编号和片段关系正确、台词与提示词一致、完整提示词可复制；只有具体缺陷才修相关部分，
   再检查受影响内容与页面。检查充分后登记最终文档并交付，不扩大无关检查或宣称未经实测的提速幅度。

例如“拿杯 → 开盖 → 饮用”可以作为一个约 10 秒的生成片段：一组必要参考图配一条完整提示词，
在提示词内写清 0–3 秒拿杯、3–6 秒开盖、6–10 秒饮用及前后状态；这不是三个生成调用。
参考图关联可以这样表达，实际图数和用途随内容决定：

| 生成片段 | 本段图序与用途 | 完整提示词中的对应说明 |
|---|---|---|
| G01 人物拿杯并饮用 | 图 1：P01 产品外形；图 2：R01 角色身份与服装；图 3：S01 窗边空间与光线 | 产品沿用 P01 的杯型与图案，角色沿用 R01 的身份与造型，在 S01 的窗边环境完成连续动作，再接完整的表演、运镜与台词说明 |
| G02 产品细节特写 | 图 1：P01 产品整体；图 2：P02 杯盖细节；图 3：S01 环境光线 | 沿用同一产品，重点表现 P02 的杯盖结构；延续 S01 光线，按本段需要写清特写运动，不引用未使用的角色图 |

这里仅示意图片与提示词的关系，不代替实际内嵌图片或一条完整生成提示词。

## 用户操作与回传

员工在自行选择的视频生成平台中使用每个生成片段的参考图组和完整提示词，生成并下载视频片段，
以后可回原话题上传。每组图片标明图序和用途，提示词明确哪张用于人物、产品或场景。
员工从片段记录或 Word 文档复制对应 prompt，并使用所关联的实际图片上传并关联到视频生成输入，再提交生成；
图片在表格或文档中显示不表示已经进入视频模型，不能仅在提示词里写“参考图片”而不传入实际图片。
图片用途写明主体参考或首帧／尾帧；员工按所选工具实际支持的入口使用，不假定所有平台都支持
相同的多图或首尾帧能力。无法承载必要参考用途时，补齐适合入口的组合画面或保留缺口，不悄悄省略。
用户后来要求项目“按方案生成”时，复用工程中已登记的原图及片段关系，通过实际选定工具的
参考素材字段传入并核对上传／关联证据；必要参考图无法关联时先报告缺口，不降为无图生成。
具体视频模型、账号、平台设置和操作方式由员工决定。该分支不依赖本机视频 MCP 的健康状态或会话，
不新增视频账号管理、提供方适配器、生产 checkpoint、队列或审批状态；原生方案交付只用受限飞书写入工具。

本轮以原生表格链接或所请求的自包含方案文件为最终交付，交付后结束执行，不后台等待、不自动生成视频。
参考图和片段提示词完成不表示视频片段已完成，不将素材／合成阶段标为完成。保留人工生成的决定，

保留原声并跳过专项；另行要求字幕时只执行相关步骤。未知来源不伪造模型或提供方回执。
