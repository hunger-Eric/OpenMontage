# 人工生成方案工作流

## 适用范围

这是独立的方案交付工作流，复用 OpenMontage 现有前期制作步骤。用户只说“我有个产品叫 X，
帮我写一份视频方案”时，即可作为常规入口，不要求用户先提出人工生成术语、枚举交付物或选择模型。
方案默认包含创作分镜、必要的真实参考图，以及各生成片段的完整可复制提示词，交付文档即完成；完整视频请求
仍走自动成片流程。用户明确要求“交给员工在网页生成”“只给我图片和逐片段提示词”时，也在参考图
与各片段提示词准备完成后交付文档，本轮任务即完成。只要求文字或先构思时尊重文字范围，不生成图。
也可在既有制作中按用户要求停在同一交接点，不增加新的生产状态或审批步骤。

示例请求：

> 我有个产品叫 X，帮我写一份视频方案。

也可点名现有入口技能，后面仍只写一句产品需求：

> 使用 ai-video-gen 技能。我有个产品叫 X，帮我写一份视频方案。

“视频方案”包含参考图、分镜和各生成片段的完整提示词；“视频文案”是纯文字交付，不生成图片或视频。
即使点名这个技能，也不把文案请求升级为带图方案；明确“只要文字”时同样只输出文字。

## 交接前

1. 信息不全时先合理设计并标明方案建议；只对实质影响内容的缺口问一个简短问题，不要求固定表单。
   不虚构真实产品规格或品牌外观；只有名称且暂无产品图时，产品视觉示意标明为概念，不当作真实商品。
2. 新需求沿用现有前期流程完成方案与分镜；已有作品则复用同一 brief、scene plan、参考分析和创作决定。
3. 按当前项目授权，复用已有参考图；缺少必要人物／产品／场景图时，用现有已选的图像工具生成或补齐。
   其他角色和场景图按方案需要制作，不为满足格式强行补图。
   沿用现有素材登记，保留实际原图与片段的对应关系；文档中的图序和用途应能追溯到工程素材。
4. 按一次人工生成的视频片段组织交接：每段准备一组必要参考图和一条自洽完整提示词，
   并给出该生成片段与已有 `scene_plan` 镜头编号的映射。段内几秒的分镜、动作和相对时间建议
   写在同一提示词中，不自动拆成独立生成任务。
5. 沿用已确认的台词、人物／产品身份、动作连续性和前后状态；只询问会实质影响交付的缺口，
   不重新询问已经确定的制作偏好。

## 交付工件

交接时提供一份自包含、平台中立、可复制的 Excel 方案，保存为
`artifacts/manual-video-handoff.xlsx`。Markdown 可保留为项目内部草稿，但不作为外部附图交付。
默认 Worker 输出附件只包含这份最终方案文档，不另列图片附件；每一行代表一个实际生成片段，
该行直接嵌入一组必要参考图，并放置对应的完整提示词。原图仍在工程内登记并供后续复用。

该 Excel 文档至少包含以下字段，每行对应一个生成片段：

| 字段 | 内容 |
|---|---|
| 片段 ID／原分镜 | 与后续回传一致的片段编号，以及关联的原分镜编号 |
| 整片位置／片段规格 | 整片中的位置、建议片段时长与画幅；段内相对节奏单独记录 |
| 场景与画面动作 | 场景、主体、动作、关键状态转换和镜头意图 |
| 内嵌参考图组 | 实际嵌入的图像，标明图序及人物／产品／场景用途 |
| 口播／对白原文 | 本片段完整台词，用户已锁定时逐字保留；无需口播则写“无”，区分画外音与现场口播 |
| 屏幕文字 | 无则写“无”；字幕／标题与口播内容分开记录 |
| 完整生成 prompt | 一条可独立复制的主体、动作、镜头、视觉、声音和前后状态提示词 |
| 前后衔接 | 与前后生成片段或原分镜的姿态、道具、方向和声音衔接 |

每一行直接嵌入对应参考图组，并放置一条可一次复制的完整 prompt；图片必须真实写入
工作簿内容，不能用本机绝对路径、项目相对路径或仅外部图片链接冒充内嵌图片。表格应设置足够的
列宽和行高以容纳图片与长文本，启用换行并冻结表头；完整 prompt 必须作为可复制文本保存，不能做成文本截图。
导出后预览工作簿，确认实际图片显示完整、片段顺序正确、表头冻结且 prompt 可复制，再登记最终文档交付。
每条提示词必须自洽，写清景别、构图、主体位置、光线／环境、人物与产品动作、运镜、
真实对白（如有）、段内相对节奏及与相邻片段的前后状态。以创作意图表达要求，不绑定某个平台的提示词语法。
口播／对白列与 prompt 中的对白必须来自同一内容依据并保持原文；仅后期添加的屏幕文字不得写成模型需要生成的画面文字。
必要拍摄声音可以归入同一生成片段；音乐沿用现有整片规划，不要求每行生成新的音乐。
不要写内部 asset 路径、MCP 参数、selector 调用、私有 receipt 或实现细节。视频提示词
与时长／画幅规格分开写；不指定视频模型、平台、账号、页面按钮或 API 参数，
不强制每段 10 秒，也不强制每段参考图数量或重新生成；可复用人物、产品和场景图。按动作复杂度、
人物／场景切换、关键细节控制或用户明确要求决定是否分段。整片范围规划与片段内相对节奏分开记录，
建议时间不是模型精确执行承诺。人工方案无需发现或选择视频提供方；图像准备仍沿用现有图像工具。
若当前执行环境没有实际导出自包含 XLSX 的能力，报告该交付缺口，不默认退回逐张图片发送。

### 模板与排版

沿用[视频方案 Excel 模板](../templates/manual-video-handoff.xlsx)，复制到项目后填写；
作品名称、产品、受众、总时长、画幅和声音方向放在表格上方，生成片段明细紧随其后。
默认保留单页工作表，按实际内容扩展行数，不要求固定镜头数或片段数。

- 使用清晰的中文字体、温暖浅色底和深色表头，以少量强调色区分层级；隐藏网格线，
  用留白和浅色行分隔组织内容，不用密集粗边框、装饰徽章或制作说明占据画面区。
- 片段编号与时间列简洁，参考图保持比例；场景、口播和完整提示词的列宽及行高按内容调整，
  保证长文本完整可读、图片不盖住文字，不通过缩小字体塞进一屏。
- 冻结表头和片段编号列，便于横向查看同一片段；提示词保存为可编辑文本，可完整复制。
- 模板示意内容和图片占位只用于说明版式，交付实际方案时替换为本项目内容及真实内嵌参考图，
  不把占位格或模板示例当作已经生成的素材。输出前逐行核对内容对应关系和实际预览。

例如“拿杯 → 开盖 → 饮用”可以作为一个约 10 秒的生成片段：一组必要参考图配一条完整提示词，
在提示词内写清 0–3 秒拿杯、3–6 秒开盖、6–10 秒饮用及前后状态；这不是三个生成调用。

## 用户操作与回传

员工在自行选择的视频生成平台中使用每个生成片段的参考图组和完整提示词，生成并下载视频片段，
以后可回原话题上传。每组图片标明图序和用途，提示词明确哪张用于人物、产品或场景。
员工从 Excel 文档复制对应 prompt，并使用其中内嵌的实际图片上传并关联到对应片段的生成输入，再提交生成；
图片在文档中显示不表示已经进入视频模型，不能仅在提示词里写“参考图片”而不传入实际图片。
用户后来要求项目“按方案生成”时，复用工程中已登记的原图及片段关系，通过实际选定工具的
参考素材字段传入并核对上传／关联证据；必要参考图无法关联时先报告缺口，不降为无图生成。
具体模型、账号、平台设置和操作方式由员工决定。该分支不依赖本机视频 MCP 的健康状态或会话，
也不新增账号管理、适配器、JSON schema、checkpoint、队列或审批状态。

本轮以自包含方案文档为最终交付，交付后结束执行，不后台等待、不自动生成视频。
参考图和片段提示词完成不表示视频片段已完成，不将素材／合成阶段标为完成。保留人工生成的决定，
不自行改回自动提交。以后回传时沿用可信素材、当前项目关系和既有续作流程；只询问有歧义的
片段与镜头的映射，不重跑已接受片段。收到视频后再按既有流程继续后期、验证和交付。

## 声音与画面约束

回传后的声音处理沿用项目[中文换声规则](omni-chinese-redub.md)，依据实际素材来源和整片语言执行，
不因员工手动生成而取消已适用的换声要求，也不扩大到其他平台或普通原片。英文／混合语言
保留原声并跳过专项；另行要求字幕时只执行相关步骤。未知来源不伪造模型或提供方回执。
交付给员工的方案只包含创作所需内容；换声、混音和验收等制作说明留在工程记录，不显示在视频画面中。
