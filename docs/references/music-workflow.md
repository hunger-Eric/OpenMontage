# 背景音乐设计与混音交接

适用于 OpenMontage 已选流水线中的背景音乐。沿用当前项目的执行器、
工具清单、声音选择和授权；方案请求不生成音乐，已接受的素材不因本规则重跑。
这份文件规定导演决策与交接方式，不代表已新增自动配乐或渲染器能力。

## 最终制作提示

在最终制作／合成提示中明确带入以下要求，并在成片画面中核对；提示文字本身不作为画面内容：

```text
成片画面只显示面向观众的产品、叙事内容和必要字幕。
不要在画面、字幕、角标或片尾卡中显示混音、节选处理、配音方式、TTS、
模型、引擎、工作流、参数、验收结果或其他制作说明。
制作与技术信息保存在工程记录或随片说明中。
```

## 音乐如何服务内容

由主导演根据脚本、画面和目标风格决定音乐的作用、情绪走向及留白。
搜索工具提供候选和来源信息，音乐模型按选定方向生成，音频工具完成确定的
裁切、循环、淡入淡出与混音；节拍、能量或响度测量不能代替选曲与情绪判断。

- 先定整片音乐方向，再安排进入、降低、起伏、留白和结束的位置。
  一首音乐可以贯穿全片并分段变化，不要求每个镜头换曲，也不固定段落数。
- 人物解释时音乐降低存在感；关键结论前可留白，结尾按实际音乐句式收束。
  无音乐也是有效选择。纯器乐、稀疏编曲可作为口播片候选，不设固定曲风。
- 使用实际剪辑和最终口播时间安排音乐。中文换声对齐完成后，再确定音乐
  避让与混音；不要把未对齐的原始 TTS 时长当作最终时间线。
- 音乐不足时可裁切、自然循环或使用多个段落，按内容判断并记录处理方式。
  不把任意循环当作完成配乐，也不为凑时长默认拉伸整条音乐或口播。

## 来源与音轨边界

复用已确认的音乐选择，包括项目内已接受的音乐。尚未选择时，按
`AGENT_GUIDE.md > Music Plan` 检查用户曲库、可用音乐搜索与生成选项，
同时允许用户提供或选择无音乐。只使用该阶段 manifest 允许且当前可用的工具；
没有相应工具时报告缺口，不在合成阶段静默换来源、模型或增加付费生成。

登记曲库、搜索所得、独立生成和原生声音底床的真实来源与授权信息。
下载成功或标称免费不证明用途已获许可。原生片段的声音不自动等于统一配乐：
它可能包含对白、环境声或不同的音乐，需要按实际内容决定用途。

音乐版权署名按实际许可执行；许可允许在画面外署名时，放在随片署名文件或发布正文中，
并与视频一并提供，不能只保存在内部工程账本。

对白、背景音乐、环境声／音效分别说明来源和处理方式：

- Omni / Flow 纯中文按[中文换声工作流](omni-chinese-redub.md)处理。
  只有已分离且不残留旧对白的原生背景素材，才可在换声后单独保留。
  原声是对白与背景混合轨时，不能承诺只删对白而完整保留背景；沿用已批准
  的去原声与配乐方案，缺少分离能力时如实说明，不重新叠入旧口播。
- 纯英文和混合语言整条保留原声，包括其中已有的音乐／环境声；
  不拆分语言段，不新增 TTS、转写、节奏对齐、嘴型同步或口播听感专项检查。
  已有原生音乐时，不默认再叠一条背景音乐。音乐安排不改变上述语言规则。

## 沿用现有工件交接

每类信息只在所属阶段保存权威值，后续引用，不复制多套可变计划：

| 工件 | 保存的音乐信息 |
|---|---|
| proposal／brief | 音乐作用、情绪方向、来源选择或无音乐；沿用 `production_plan.music_source`，细化说明可放 `metadata.music_plan` |
| asset_manifest | 音乐资产的 `id`、`path`、`source_tool`、`scene_id`、实际 `duration_seconds`，以及适用的 `provider`、`model`、`license`、`original_url`；署名与来源回执引用可放 `metadata.music_sources` |
| edit_decisions | `audio.music` 中已有的资产、基础音量、fade 与 ducking 配置；分段意图放 `metadata.music_plan`，引用资产 ID，注明源音频范围、时间线范围、段落作用、音量变化、留白与循环方式 |
| render_report | 在 `metadata.music_mix` 记录实际 runtime、原生分轨或预混音方式、被消费的音轨及混音回执引用、实际生效的 fade／ducking 和未实现项；实际试听发现放 `verification_notes`／`warnings` |

遵守当前 schema：`music_source.source_type` 尚无搜索／原生底床枚举时，
在 proposal／brief 的 `metadata.music_plan` 与决策日志记录真实来源，
不填不存在的枚举，也不误标为另一种来源。`audio.music` 当前以单个对象
组织；metadata 中的分段计划是交接说明，不会自动触发多段配乐。

合成阶段应将计划显式映射到当前工具支持的请求。需要分段音轨时，使用
已有且获准的音频处理入口准备素材或混音，再引用实际输出；不把新增 metadata
当作渲染器已经消费的参数。不需要额外计划文件或重复审批。

## 混音执行与验收

保持已锁定的画面渲染 runtime。是否使用音频预处理与画面 runtime 是不同
选择：使用现有 `audio_mixer` 不意味着把 Remotion 视频改成 FFmpeg 视频。

- 已查的内置 `Explainer`／`CinematicRenderer` 使用固定音乐音量和淡入淡出，
  未按口播动态压低音乐。仅填写 `ducking` 不能认定它已生效；自定义 composition
  的能力以实际实现为准。
- 固定音量已经适合该片时，可沿用原生音频组件。需要动态避让且该阶段允许
  `audio_mixer` 时，可用现有混音路径执行，并让既定 composition 消费输出。
  播放预混音一次，关闭被它取代的重复音轨，保留正确的时间线与字幕来源。
  工具或 composition 不支持已批准的效果时报告缺口，不静默忽略，也不换 runtime。
- 音量、压低幅度、响度和 fade 时长依据素材与约定风格选择；示例数字和
  测量阈值不变成全项目固定值。参数请求、实际执行和可听效果分别记录。
- 检查实际成片中的音乐是否符合内容、进退是否自然、是否重复叠加或截断，
  是否遮住讲话。英文／混合语言只评价配乐安排，不新增口播听感或同步专项。
  未实际试听的音乐效果标为未验证；成功回执、音轨存在、节拍或响度数据
  均不能单独证明音乐合适。
