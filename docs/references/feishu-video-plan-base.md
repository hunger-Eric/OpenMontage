# 飞书原生视频方案交付

## 入口与交付

飞书入口的带图视频方案默认直接写入多维表格，使用 `feishu_video_plan`，不先制作 Word 或 Excel。
用户仍只需说“我有个产品叫 X，帮我写一份视频方案”；正文、图片与提示词沿用
[通用视觉策划流程](visual-video-planning.md)，视频模型与员工使用的平台仍由后续实际生成决定。
“视频文案”保持纯文字，不因接入多维表格而生成图片。

每个项目新建独立的一份 Base，包含三张由看板维护的关联表，不把不同话题的方案写进同一批记录。
对用户只交付独立的“视频方案看板”网页入口，页面不显示“方案总览”“参考资产”“生成片段”的数据表侧栏。
三张表仅为后台数据源，保留以支撑图片、正文和关联，不作为用户交付页面，也不要求用户进入 Base。
模板配置的 `template_board_url` 是模板的独立展示入口，不能当作新项目的交付链接。

| 数据表 | 看板提供的内容（数据源，不是用户的主要操作入口） |
|---|---|
| 方案总览 | 作品、产品、受众、总时长、画幅、视觉与声音方向、故事主线 |
| 参考资产 | 稳定图片编号、类型、主体名称、角度／状态、设定与用途、来源或图片准备提示、实际图片附件 |
| 生成片段 | 片段编号、整片位置与建议规格、原分镜、场景／动作／起止状态、关联资产、图序与用途、口播／对白、屏幕文字、完整视频提示词、衔接与按需关键画面准备 |

片段的“参考资产”使用飞书真实关联字段，指向资产记录，不只存一串 `P01/R01/S01` 文本。
“参考图序与用途”另保留本段顺序与约束；关联记录顺序不代替明确的图片使用顺序。
实际图通过附件接口上传，每份资产只在资产表上传一次；多个片段复用其关联，不反复上传同一图。
角色图、场景图、产品图及按需首帧继续明确用途；多维表格里的图片不会自动进入视频生成模型。

成功后沿用既有 Worker 结果文本优先返回本项目看板的实际链接与完成范围，不另发送图片，不默认输出 Office 文件。
最终回复第一行应直接给出本项目已验证的独立看板链接，不只说“方案已准备好”或引用本地文件路径。
等待完整方案确认时，链接同样放入 `NEEDS_INPUT` 的问题正文，`artifacts` 保持为空。
消息与附件运输归 Worker，不等于禁止业务执行器通过既有能力创建用户要求的云端看板。
若当前执行环境的交付约束与此冲突，报告具体冲突，不默认让用户省略看板或用 HTML 附件代替；
未取得真实入口时不得声称看板已交付。
本轮方案交付即结束，不自动调用视频提供方或后台等待。以后回同一话题提供视频或要求“按方案生成”，
沿用本地登记的原图、资产与片段关系继续；线上关联记录不代替实际视频参考上传／绑定证据。

## 职责与实际接口

模型负责需求理解、创意、内容组织、图片选择、图像生成、构图与完整提示词。
工具代码只负责本地字段校验、上传、批量写入、记录关联、回执和必要读回，不重新编排或改写台词。
复用现有生产项目与可信素材；不建立另一套视频 pipeline 或提供方路由。
正式方案的 `plan` 必须由同一项目的既有研究、已确认方案、脚本、分镜和登记参考资产映射而来，
具体关系见[既有阶段衔接](visual-video-planning.md#与现有项目阶段衔接)。缺少内容时回所属阶段补齐；
适配器不负责运行研究、推断阶段通过或自动把参考图交付记为整个素材阶段完成。

适配器通过 `tools/feishu_base_client.py` 的 Python HTTP 封装调用官方 Base v3 和 Drive 媒体接口。
不调用原生 CLI、npm shim 或 shell，不按操作系统寻找可执行文件，也不回退到桌面 CLI 配置。
不从 Bridge 读取密钥，不暴露通用 raw API，不新增 Bridge 业务端点，不重启或部署 Bridge。
调用必须明确 `user` 或 `bot` 身份并全程保持；本地配置状态不证明授权可用，实际权限与资源访问以
原身份接口结果为准。当前入口使用已授权身份，缺权限时报告具体缺口，不静默换身份。

用户身份默认通过 `tools/feishu_auth.py` 的 Python 设备授权流程建立，固定应用和原用户 open_id。
首次安装由可信宿主调用 `python -m tools.feishu_auth configure`，通过标准输入传入
`app_id`、`app_secret`、`user_open_id` 和可选 `brand`；命令参数不接收密钥，输出仅包含公开绑定。
随后 `begin` 返回原样授权链接，用户完成授权后 `finish` 核对身份并激活；`status` 不输出令牌。
授权完成前用 `user_info` 核对同一用户；令牌与应用凭据保存在 Python keyring 的系统安全存储中，
公开绑定配置默认位于 `~/.config/openmontage/feishu-auth.json`，可用 `FEISHU_AUTH_CONFIG` 指定。
过期前由 Python 刷新；刷新结果不明时保留刷新锁，停止重放。Windows 长令牌按安全存储限长分片，
各片写完后才激活清单，失败时保留旧凭据；不把令牌和密钥写入配置文件。
执行环境也可通过 `FEISHU_APP_ID` 和所选身份对应的 `FEISHU_USER_ACCESS_TOKEN` 或
`FEISHU_TENANT_ACCESS_TOKEN` 显式注入授权；`FEISHU_BRAND` 默认为 `feishu`，国际版使用 `lark`。
宿主也可向 `FeishuBaseClient` 注入返回 `FeishuCredentials` 的 Python provider。
bot 创建副本必须绑定明确的 `user_open_id`（环境配置为 `FEISHU_USER_OPEN_ID`）；复制与用户授权分别登记回执。
无法确认受让人时在复制前停止，用户授权失败时保留副本与具体步骤，不再复制第二份。
凭据不进入模型输入、项目回执或版本库；不从原生 CLI 的私有存储导出令牌。
缺少所选身份凭据时在创建项目写入回执之前失败，不把本地配置错误登记成已提交、结果不明的写操作。
已有桌面 CLI 登录不代表 Python 路径已经接通；没有同身份授权与真实接口读回时，验收保持未验证。

接口分两步，均由既有制作执行器调用，不让用户手工运行命令：

1. `initialize`：从固定看板模板复制本项目的空内容 Base，保留看板、视图和三张表的样式，读取并登记副本的实际 table ID；不会声称方案已完成。
2. `publish`：校验模型已确定的方案与实际原图后，批量写正文，上传资产图，建立真实片段关联。

第一次初始化后复用本项目回执。不同项目分别保存自己的 Base 身份；同项目并发调用由本地互斥保护。
该互斥只防止同一份交付重复写，不新增生产队列或用户审批状态。

### 固定看板模板

模板身份由 [`feishu-video-plan-base.json`](../templates/feishu-video-plan-base.json) 登记，
执行器默认复用这一份模板。换产品时只生成或更新创意内容和所需参考图，不再次调用页面 AI 设计排版。
模板中的咖啡方案是样式示例；新项目通过 Python `copy_base` 的 `without_content=true` 只复制结构，再填入自己的内容。
产品、角色、场景和片段数量由实际方案决定，不固定为四段、两张图或某个示例品牌。

复制后通过 Python `list_tables` 与 `list_fields` 读取副本身份，并检查片段的关联字段指向副本资产表。
不把模板表 ID、旧 record ID 或旧图片链接写到新项目。模板不可用、结构不完整或复制结果不明时停止，
不能悄悄创建没有看板的普通 Base。已有项目沿用自己的回执，不强制迁移或重建。
配置中的 `page_name` 用于指明用户查看的看板；结构检查不替代实际页面显示验收。
当前 `list_tables` 只枚举数据表，不返回看板的 `wbp` 页面 ID。浏览器可用时，打开副本，
点击其 `page_name` 对应的侧栏页面，登记后台看板 URL；再使用页面原生发布入口，读取本项目真实的
`/share/base/webpage/` 链接，打开后检查无数据表侧栏、图片和完整提示词可用，才作为用户交付入口。
不猜页面 ID，不沿用模板自己的页面 ID 或独立网页链接。默认沿用当前项目的组织内访问范围，
不为单页交付自动扩大到互联网公开。已发布的本项目网页复用原链接，不重复创建页面。
浏览器不可用或发布失败时保留已经写入的方案，报告“独立看板入口未验证”及具体缺口；
后台 Base 链接只作维护证据，不以它替代用户要求的单一看板入口。

看板外层每个片段只承担静态预览，标题、时间、必要图片和简述默认可见，不需要用户手动展开；同时只提供唯一的“打开操作面板”入口。
外层不重复放复制、下载、提示词展开或其他查看内容的按钮，也不把长提示词重复铺在卡片上。
打开后，片段详情面板是完整操作面板：在同一个面板内同时展示实际参考图、图片用途与顺序、画面动作、口播、
屏幕文字和完整提示词，并提供这些内容的取用方式。每张图的复制、保存原图和放大查看使用常驻文字按钮，
不只在悬停时显示图标。用户完成一段视频素材交接时不应被要求打开底层资产表或
片段表。模型整理“口播对白”时只写可朗读的台词，制作方式和配音说明放在声音方向或建议规格；工具传输原文，
不自行重写口播；口播在面板内只展示，不提供专用选中、复制控件或复制提示。图片复制或保存必须基于真实图片本身，
不把图片 URL 当成复制结果；浏览器限制图片复制时，在同一面板保留原图的右键复制／另存为入口并明确提示。
完整生成提示词使用面板内已经展示的原文 DOM，点击“选中”直接全选，只给简短复制提示，不追加重复 textarea、
文本框或弹窗；受浏览器限制时保留同一面板内可见原文与 Ctrl+C 回退，不以 URL 或成功图标代替真实取用，
也不跳转到其他数据表。

模板的公开权限与每个项目的内容交付是独立事项。本次用户授权模板为“互联网上获得链接的人可编辑”，
权限设置必须以飞书真实读回为准；不把公开模板配置标记当作权限验证。普通方案仍由既有 Worker 返回
项目链接，不增加新的群发入口、消息协议或 Bridge 部署步骤。

### 执行器调用

调用前先完成[原有前期阶段](manual-video-handoff.md#必须先执行原有前期阶段)。`initialize`／`publish`
是交付适配器调用，不是研究、方案、脚本或分镜阶段的替代入口；它们成功不证明这些阶段已执行。
先做 stage artifact 与必要参考素材，再整理工具入参；禁止先写 `plan`，之后为它补造研究或审批记录。

在既有 agent 制作步骤中，先把模型已确定的总览、实际原图与片段关系机械整理为工具 `plan` 入参，
不增加新的 Bridge 消息协议。字段见[受限适配器](../../tools/feishu_video_plan.py)的校验与映射方法；
正文来自同一项目 brief／scene plan，图片来自本次可信且已登记的素材，不能重新设计以适配字段。
继而通过既有 registry 调用，检查每次 `ToolResult.success`；不能只写“将调用”便结束：

```python
from tools.tool_registry import registry

registry.ensure_discovered()
tool = registry.get("feishu_video_plan")
if tool is None:
    raise RuntimeError("feishu_video_plan is not registered")
created = tool.execute({
    "operation": "initialize", "project_dir": project_dir,
    "identity": identity, "title": plan["overview"]["title"],
})
if not created.success:
    raise RuntimeError(created.error)
published = tool.execute({
    "operation": "publish", "project_dir": project_dir,
    "identity": identity, "plan": plan,
})
if not published.success:
    raise RuntimeError(published.error)
base_url = published.data["url"]
```

随后以返回的真实表／record ID，通过同身份 Python HTTP 读回检查正文、图片附件与片段
关联，并打开 Base 检查实际图片。`published` 只表示写入步骤完成，不单独证明 UI 可见或视频可用。
接口读回通过后，按上面的页面入口步骤获取本项目真实独立看板网页 URL，与方案完成范围放入原执行器的最终回复文本，
由既有 Worker 返回原话题；`base_url` 只留作后台维护证据，不作为用户交付入口。
浏览器不可用或缺少登录态时，明确标为“独立看板入口未验证”，保留已写入且读回通过的内容及缺口；
不因此重新创建 Base、要求额外确认或转入 Office 制作。
不自建发送消息端点，不把私有回执当作给用户的额外附件，不以 Base 初始化成功代替完整方案。

## 回执、失败与验收

在本项目 `artifacts/feishu-video-plan-delivery.json` 保留 Base、数据表、资产／片段记录身份、
输入完整性摘要和每个写操作结果，不包含访问令牌或密钥。原始图片继续在工程保留。
确定成功的步骤可复用；相同输入重复调用不再创建 Base、追加记录或重复上传图片。

有副作用的请求先登记正在执行的操作；超时、连接中断或返回不明时保存不确定结果，停止自动重试，
不重复创建、写入或上传。输入发生变化时不静默覆盖已发布记录；保留当前内容并报告需要续改的范围。
部分成功不表示整份方案已发布，返回已经得到的身份与具体缺口，保留已接受素材。

工具本地检查资产与片段编号唯一、引用有效、完整 prompt 非空、所需图片真实存在且来自本项目。
缺图或错引用先在本地停止，不把占位或文字当作完成的视觉方案。写前确认真实字段结构；
附件走专门上传接口，关联字段使用接口返回的真实 record ID，正文按表批量写入。

实际联调至少检查一份方案的正文、附件与关联读回，有可用登录态时再打开 Base 检查用户可见结果。
模拟测试、接口成功和 Base 链接分别证明各自层级，不自动证明图片显示、权限可用或视频效果。
API 不支持的列宽、行高等界面外观不伪造参数；本次接口交付不承诺自动还原 Word 排版。

该路径省去 Office 排版、导出和文档渲染检查；图像生成和模型策划仍需实际执行。
记录真实接口耗时，后续用完整方案实测总耗时，不承诺未经测量的提速比例。
用户明确要 Word／Excel 时才沿用[对应文件工作流](manual-video-handoff.md)，不自动制作多个版本；
原生 API 不可用时保留方案与具体错误，不静默退回耗时的 Office 路线。

## 官方接口依据

使用官方接口和官方实现核对当前 `base/v3` 接口形状，
不混用历史 `bitable/v1` 的数字字段类型或附件 CellValue 格式。
官方客户端与 API 入口：[飞书官方 CLI](https://github.com/larksuite/cli)、
[飞书多维表格文档](https://open.feishu.cn/document/server-docs/docs/bitable-v1/bitable-overview)。
